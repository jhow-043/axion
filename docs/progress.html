Riscos e Alertas
🟢
WebSocket multi-instância (P14) — concluído e mergeado
Canal notifications:{user_id} via Redis pub/sub implementado em P14. Risco mitigado; monitorar latência em produção multi-instância.
🟢
Kanban drag-and-drop (P15) — dnd-kit implementado
Transições de estado via drag-and-drop usam dnd-kit com validação de state machine no backend. Risco de conflito concorrente mitigado com otimistic update + rollback no frontend.
🟠
Isolamento de tenant crítico — INV-01
Qualquer bypass do BaseRepository é brecha de segurança. Reviews de PR devem incluir checklist de isolamento em cada módulo novo.
🟠
Jobs Celery — tenant_id explícito (INV-04)
ContextVar não existe no worker Celery. P12 (SLA jobs) e P13 (auto-fechamento) devem sempre receber tenant_id como argumento explícito.
🟡
Concorrência no auto-fechamento (P13)
Solicitante pode aprovar exatamente quando Celery job executa auto-close. Usar SELECT FOR UPDATE ou pré-condições de estado para evitar dupla transição.
🟡
Performance de dashboards (P15–P16)
Queries de agregação em tabelas de tickets grandes. Índices compostos foram planejados desde P09. Considerar views materializadas em P15/P16 se volumes justificarem.
